What the cockpit does

A local web page served from your own machine, over every Claude Code session on it. It reads what each session reports and acts through the session itself, so nothing leaves your computer.

  • Who needs you, first. Permission requests and questions as cards, oldest first, with the agent's reason, a diff for edits and a badge on risky commands. Allow, deny or answer with a click or A / D.
  • Steer any session. Send a prompt, or type / for the session's own slash commands, in a drop-up like Claude Code's.
  • Workstreams. Start an agent in a fresh git worktree on its own branch, watch each one, rename or remove it.
  • Changes and PRs. Lines changed per agent and file, the pull request with CI and reviews, and squash-merge when it's green.
  • Health. Agents that look stuck, loop on the same failing command, or fill their context are flagged, and the timeline shows who worked and who waited on you.
  • The whole fleet. Table, cards or timeline; one prompt to many agents; jump to a session's window or attach to a background one. System, light or dark, remembered.

Answer from the cockpit, not the terminal

When an agent the cockpit launched wants permission, the question comes to you, not to a terminal nobody is watching.

Install

One line adds the marketplace and installs the plugin. Install it everywhere: every session then reports to the cockpit and can be steered from it.

claude plugin marketplace add alaturqua/tower-mods && claude plugin install tower@tower

On Windows, PowerShell runs the two commands one after the other with a semicolon. In Command Prompt, or PowerShell 7, you can use && as on macOS and Linux.

  • Open the cockpit: /cockpit in any session starts it and opens your browser. It listens on this machine only, behind a one-time link.
  • Needs: Node.js 18 or newer for the cockpit, and gh for pull requests. Sessions started before installing need a restart to report and receive.
  • Launching agents: Claude Code must have been trusted in a repository once (open Claude Code there and accept the prompt) before the cockpit can start agents in it.
  • Early access: Claude Code mods are new; the API can change between releases. See the changelog.

Help: update, restart, stop

The cockpit is a small server that keeps running after the session that started it. Updating the plugin doesn't touch it, so it needs one step to pick up a new version.

Update

Update the plugin, then reload it in every open session:

claude plugin marketplace update tower && claude plugin update tower

Then type /reload-plugins in your sessions and /cockpit in any of them. A cockpit of an older version is replaced by the new one on its own, and your open browser tab keeps working.

Restart or stop

In any session:

/cockpit restart
/cockpit stop

From a shell, with the plugin folder in place of the placeholder:

node "<plugin folder>/cockpit/server.mjs" --restart
node "<plugin folder>/cockpit/server.mjs" --stop

Stopping ends only the server. Your agents keep running and keep their status files; the cockpit finds them again when it starts.

When something is off

  • The page says forbidden: open it through /cockpit, which carries the link's token. The link is also in ~/.claude/tower/cockpit.json.
  • The port is taken: start it on another one with --port 4748, or set TOWER_COCKPIT_PORT.
  • A prompt stays "Queued": that session started before Tower was installed. Restart it or run /reload-plugins in it.
  • A launch fails: open Claude Code in that repository once and accept the trust prompt.
  • No pull requests show: install the GitHub CLI and run gh auth login.
  • The page looks old after an update: run /cockpit restart, then reload the tab.
  • Uninstall: /cockpit stop, then claude plugin uninstall tower.

Settings are in /config under the plugin, and the README lists each one. Still stuck? Open an issue with your version from claude plugin list.
